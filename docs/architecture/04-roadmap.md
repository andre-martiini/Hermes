# Hermes Roadmap Revisado

## 1. Princípio do Roadmap

O roadmap foi reorganizado para reduzir risco estrutural. A prioridade agora não é “implementar tudo”, mas criar uma sequência em que cada fase desbloqueia a seguinte.

## 2. Sequência Recomendada

### Fase 0+

Objetivo:

- consolidar visão;
- definir boundaries;
- fixar domínios iniciais;
- definir source-of-truth;
- fechar modelo operacional mínimo;
- fechar política inicial de autonomia.

Entregáveis:

- visão e boundaries;
- modelo canônico;
- política de risco e tooling;
- roadmap revisado.

Critério de saída:

- toda nova iniciativa consegue responder:
  - qual domínio atende;
  - qual objeto canônico cria ou altera;
  - qual ferramenta usa;
  - qual modo de aprovação exige.

### Fase 1

Objetivo:

- padronizar ingestão nos canais já reais.

Escopo inicial:

- texto;
- arquivos;
- áudio;
- WhatsApp;
- Drive;
- links.

Entregáveis:

- contrato único de intake;
- metadados mínimos obrigatórios;
- distinção formal entre original e derivado.

Critério de saída:

- qualquer entrada cai na mesma esteira lógica de registro e preparação.

### Fase 2A

Objetivo:

- estabelecer memória documental versionada antes do grafo pleno.

Entregáveis:

- artifacts;
- intake records;
- decision records;
- execution records;
- knowledge nodes simples;
- política de proveniência e versionamento.

Critério de saída:

- o Hermes consegue recuperar contexto confiável com vínculo de fonte e versão.

### Fase 3

Objetivo:

- formalizar catálogo local de ferramentas e política de aprovação.

Entregáveis:

- tool registry inicial;
- matrizes de risco e autonomia;
- regras duras de bloqueio;
- contratos das primeiras ferramentas homologadas.

Critério de saída:

- nenhuma execução relevante acontece fora de ferramenta registrada e política definida.

### Fase 4

Objetivo:

- implantar roteamento híbrido e cartão de contexto.

Entregáveis:

- score de clareza;
- score de contexto;
- score de impacto;
- plano de execução;
- apresentação seletiva de confirmação.

Critério de saída:

- o Hermes não pede confirmação para tudo e não executa no escuro.

### Fase 2B

Objetivo:

- enriquecer a memória com relações explícitas e vigência temporal.

Entregáveis:

- edges;
- consultas relacionais;
- política temporal;
- contexto relacional navegável.

Critério de saída:

- recuperação passa a incluir relação, uso, substituição e histórico.

### Fase 5

Objetivo:

- validar o fluxo de correção de código com base cognitiva já estável.

Entregáveis:

- espelhamento incremental do repositório;
- pacote de issue;
- entrega revisável com resumo, diff e arquivos impactados.

Critério de saída:

- bugs dispersos conseguem virar proposta técnica consistente e auditável.

### Fase 6

Objetivo:

- formalizar POPs adaptativos.

Entregáveis:

- modelo de procedimento;
- primeiros POPs executáveis;
- reaprendizado após correções humanas.

Critério de saída:

- o Hermes passa a propor encaminhamento fundamentado, não resposta genérica.

### Fase 7

Objetivo:

- ampliar autonomia com segurança operacional.

Entregáveis:

- matrizes maduras de decisão;
- bloqueios operacionais;
- segregação por domínio.

Critério de saída:

- o sistema sabe agir, sugerir ou parar com consistência.

### Fase 8

Objetivo:

- consolidar observabilidade e melhoria contínua.

Entregáveis:

- logs e trilhas completas;
- revisão de obsolescência;
- feedback loop formal;
- indicadores de qualidade.

Critério de saída:

- cada resposta ou ação relevante deixa rastro inteligível de contexto, decisão e aprendizado.

## 3. Casos-Piloto

### Caso A: correções em sistemas

Valida:

- ingestão multimodal;
- memória técnica;
- issue packet;
- agente especializado;
- revisão antes de ação externa.

### Caso B: encaminhamento de processos

Valida:

- leitura documental;
- recuperação de procedimento;
- geração de minuta;
- checkpoint obrigatório.

### Caso C: ingestão de materiais densos

Valida:

- preparação;
- proveniência;
- versionamento;
- base de reutilização futura.

## 4. Regra de Priorização

Toda fase nova só deve avançar se não degradar:

- governança;
- proveniência;
- auditabilidade;
- clareza de contratos.

Se houver conflito, a prioridade é estabilizar a base antes de expandir capacidade.
